# 最终可长期复用 · 思维导图测试用例生成通用提示词

## 版本一：标准完整版（团队共享、正式交付，推荐长期复用）

### 一、基础要求

1. 输出格式：仅使用**空格缩进**区分节点层级，无任何 Markdown 符号、特殊标记、注释、分隔线，内容可直接复制导入 XMind。
2. 内容原则：**100% 沿用原始需求文本**，不删减、不修改、不润色、不合并、不新增业务逻辑；完整保留正文、链接、单号、备注、技术疑问、测试点、边界场景、公式、示例、约束规则。
3. 顺序原则：严格遵循**需求原文的章节/页面顺序**，不调整原有排版逻辑。

### 二、统一层级定义（全局通用，所有需求强制执行）

| 节点层级 | 定位 | 适用内容 |
| ---- | ---- | ---- |
| 一级节点 | 总标题 | 单据编号+日期+业务名称（需求总主题） |
| 二级节点 | 大模块 | 需求、业务逻辑、功能模块、注意事项等一级分类 |
| 三级节点 | 章节/页面/核心大类 | 文档章节、系统页面、业务角色、计算分类等 |
| 四级节点 | 细分条目 | 字段、规则、配置项、操作项、基础说明 |
| 五级及以下 | 补充内容 | 内嵌说明、分步流程、疑问点、取值场景、校验规则、异常场景、验证要点 |

补充规则：同一节点下存在多条内容、内嵌描述、分支场景时，**全部向下拆分为子节点**，禁止大段文本堆砌。

### 三、固定结构模板（分场景复用，覆盖 90% 业务需求）

#### 场景 1：完整业务需求（含文档、业务逻辑、系统页面，主流场景）

```
一级：单据编号+日期+业务总名称
	二级：需求
		三级：需求文档（附链接）
		三级：技术文档（附链接）
		三级：文档章节（概述/范围/背景等）
			四级：章节原文内容
				五级：内嵌说明、补充备注
	二级：核心业务逻辑（计算/流程/规则类）
		三级：前提条件/时间周期
		三级：业务角色/分类
			四级：基础说明
			四级：参数/公式/配置
				五级：数据源、取值、异常场景、疑问点
		三级：分场景规则（情况1/2/3）
			四级：场景描述、示例
			四级：执行步骤、计算逻辑
			四级：验证要点
		三级：配套配置规则、数据来源
	二级：功能模块（系统页面，多页面依次排列）
		三级：页面编号+页面名称
			四级：功能描述
				五级：原型链接、补充示例
			四级：菜单位置
			四级：查询条件
				五级：单个查询项
					六级：选项、状态分类
			四级：列表数据
				五级：列表字段（逐条拆分）
					六级：字段说明、场景、疑问
				五级：操作按钮
					六级：页面能力、可改/不可改项
			四级：新增页面字段
				五级：单个字段（保留下拉框/文本框/必填/多选等标注）
					六级：约束规则、互斥逻辑、取值、唯一性校验
				五级：新增场景验证
			四级：修改页面
				五级：可修改内容
				五级：不可修改内容
				五级：状态操作（启用/禁用）、切换逻辑
			四级：全页面验证项（查询、配置、联动等）
	二级：注意事项/研发提醒
		三级：特殊规则、异常处理、汇总要求
```

#### 场景 2：纯系统页面需求（仅配置页/列表页/功能页）

```
一级：单据编号+日期+页面名称
	二级：基础信息
		三级：功能描述
		三级：原型链接/提示语
		三级：菜单位置
	二级：页面功能拆解
		三级：查询条件
		三级：列表数据
		三级：新增字段
		三级：修改能力
		三级：验证场景
```

#### 场景 3：纯业务规则需求（无系统页面，仅算法/流程/计算）

```
一级：单据编号+日期+业务名称
	二级：文档信息
		三级：需求链接、版本、背景
	二级：业务规则
		三级：适用范围、前提条件
		三级：主体分类
			四级：各项规则、参数、公式
		三级：分场景逻辑
		三级：边界/异常场景
		三级：校验要求
```

### 四、细分内容拆分规范（高频内容统一处理）

1. **字段类**：字段名+原生属性（下拉框/文本框/必填/多选）保留在同一节点；字段约束、互斥规则、取值范围、测试场景下沉为子节点。
2. **状态类**：生效、禁用、启用/禁用切换，单独拆分子节点，补充切换逻辑与验证点。
3. **公式/示例**：计算公式、金额、占比、数字示例原样保留；配套的计算校验、拆分逻辑下沉子节点。
4. **批量/导入功能**：文件格式、字段要求、成功/失败场景、数据更新规则逐层拆分。
5. **疑问/备注类**：需求内的思考、疑问、临时标注，统一放在对应条目下作为最深层级节点。
6. **重复文本**：原文重复内容原样保留，不合并、不删除。

### 五、强制禁忌（所有需求统一遵守）

1. 不使用任何代码块、markdown 标签、特殊符号、分割线。
2. 不调整需求原文的章节、页面、条目顺序。
3. 不遗漏单号、链接、日期、备注、测试点、边界场景。
4. 不新增需求外的业务规则、场景、逻辑。
