# 需求文档维度技能

## 功能

此技能用于管理需求文档维度的相关操作，包括：
- 需求分析和整理
- 需求文档编写和格式化
- 需求版本控制和变更管理
- 需求追踪和状态更新
- 需求文档审查和验证

## 使用场景

当用户需要：
- 分析和整理项目需求
- 编写规范的需求文档
- 管理需求变更和版本控制
- 追踪需求实现状态
- 审查和验证需求文档质量

## 使用示例

### 需求分析和整理

```bash
# 创建需求分析文档
mkdir -p 需求文档/分析

# 编写需求分析报告
Write-Output "# 需求分析报告" > 需求文档/分析/需求分析报告.md
Write-Output "\n## 业务背景" >> 需求文档/分析/需求分析报告.md
Write-Output "\n## 功能需求" >> 需求文档/分析/需求分析报告.md
Write-Output "\n## 非功能需求" >> 需求文档/分析/需求分析报告.md
Write-Output "\n## 数据需求" >> 需求文档/分析/需求分析报告.md
```

### 需求文档编写

```bash
# 创建需求文档目录结构
mkdir -p 需求文档/正式文档

# 编写需求规格说明书
Write-Output "# 需求规格说明书" > 需求文档/正式文档/需求规格说明书.md
Write-Output "\n## 1. 简介" >> 需求文档/正式文档/需求规格说明书.md
Write-Output "\n## 2. 功能需求" >> 需求文档/正式文档/需求规格说明书.md
Write-Output "\n## 3. 非功能需求" >> 需求文档/正式文档/需求规格说明书.md
Write-Output "\n## 4. 数据需求" >> 需求文档/正式文档/需求规格说明书.md
Write-Output "\n## 5. 范围限定" >> 需求文档/正式文档/需求规格说明书.md
Write-Output "\n## 6. 验收标准" >> 需求文档/正式文档/需求规格说明书.md
```

### 需求版本控制

```bash
# 查看需求文档状态
git status 需求文档/

# 添加需求文档更改
git add 需求文档/

# 提交需求文档更改
git commit -m "更新需求文档：添加新功能需求"

# 推送需求文档更改
git push
```

### 需求追踪

```bash
# 创建需求追踪矩阵
Write-Output "# 需求追踪矩阵" > 需求文档/管理/需求追踪矩阵.md
Write-Output "\n| 需求ID | 需求描述 | 实现状态 | 测试状态 | 备注 |" >> 需求文档/管理/需求追踪矩阵.md
Write-Output "|-------|---------|---------|---------|------|" >> 需求文档/管理/需求追踪矩阵.md
Write-Output "| RQ001 | 用户登录功能 | 进行中 | 未开始 | - |" >> 需求文档/管理/需求追踪矩阵.md
Write-Output "| RQ002 | 数据查询功能 | 未开始 | 未开始 | - |" >> 需求文档/管理/需求追踪矩阵.md
```

## 注意事项

- 确保需求文档结构清晰，内容完整
- 定期更新需求文档以反映最新的需求变更
- 使用版本控制工具管理需求文档的变更历史
- 建立需求追踪机制，确保所有需求都能被实现和测试
- 定期审查需求文档，确保其准确性和可行性

## 最佳实践

- **需求收集**：采用多种方式收集需求，包括访谈、问卷调查、原型设计等
- **需求分析**：对收集的需求进行分析和整理，识别需求之间的关系和依赖
- **需求文档化**：使用规范的格式编写需求文档，确保文档的可读性和可维护性
- **需求验证**：与相关方验证需求的准确性和完整性
- **需求管理**：建立需求管理流程，包括需求变更控制、版本管理和状态追踪

## 常见问题

### 需求变更频繁
- 建立正式的需求变更流程
- 对变更进行影响分析
- 及时更新需求文档和相关文档

### 需求不明确
- 与需求提出方进行充分沟通
- 使用原型和示例来澄清需求
- 编写详细的需求说明，避免模糊不清的描述

### 需求追踪困难
- 建立需求追踪矩阵
- 使用专业的需求管理工具
- 定期更新需求状态，确保追踪的准确性
